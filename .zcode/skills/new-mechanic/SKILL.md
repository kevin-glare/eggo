# Новая игровая механика Eggo

Пройдись по чеклисту сверху вниз. Всё, что меняет состояние или баланс, проходит
через все пункты; чисто визуальные изменения — только пункт про UI.

## 1. Числа баланса — в config.ts

Любое число, влияющее на баланс (скорости, пороги, длительности, награды,
кулдауны), добавляется в `src/game/config.ts` с комментарием, а не в логику.
Для проверки в dev используй `DEV_CONFIG` (время ×60) — не жди реальных часов.

## 2. Логика — в src/game/, чистая

- Новые функции: `state → new state`, без мутаций, без React/DOM/localStorage.
- Тест пишется до реализации, когда задача позволяет (`tests/`, Vitest).
- Новое поле в `PetState` → **обязательная нормализация в deserialize**
  (`src/game/storage.ts`), чтобы старый сейв не падал и не обнулялся, +
  тест «старый сейв читается». Ключ сейва `tamagotchi.save.v1` не переименовывать.

## 3. Запреты и кулдауны — guard в движке

- Проверка «можно ли» живёт в `src/game/actions.ts` и возвращает
  `ActionResult{ok, reason}`; UI показывает тост по `reason`.
- Кнопки НЕ дизейблить: игрок может тапнуть и получить объяснение.
- Частичная выгода — ок (например, помыл немного грязи).

## 4. Механика должна самообъясняться

До первого успеха игрок видит подсказку; снимается только когда игрок сам
сделал действие. Паттерн — `src/ui/hints.ts`: добавь новый `kind`, показывай
пока `isHintDone` false, вызови `markHintDone` после первого успеха игрока
(не после показа подсказки).

## 5. Если механика должна давать знать о себе извне (пуши)

- Решение «пора ли слать» — в `src/game/notifications.ts` (чистая функция,
  тестируется отдельно).
- Отправка — только в `worker/src/pushes.ts`; воркер шлёт не больше одного
  важнейшего уведомления за крон, уважает тихие часы (22–9 по utc_offset).
- Новые типы уведомлений не должны дублировать более критичные.

## 6. UI-слой — тонкий

- Экран/кнопки/анимации в `src/ui/`, только рендер состояния и вызовы действий.
- Анимации действия — в `PetCanvas.tsx` (GSAP-твины); если нужен новый арт
  питомца — через «гены» в `src/game/appearance.ts` с нормализацией старых
  сейвов и нейтральным яйцом (EGG_PALETTE, цвет не палится до вылупления).

## 7. Процесс

- Один этап плана = один коммит; владелец ревьюит diff между этапами.
- `git push` — только по явной просьбе владельца.
- Перед коммитом: `npm test` (TZ-зависимые тесты — с `TZ=UTC`).
